## Context

当前为无构建步骤的 Manifest V3 扩展。仪表盘顶部为问候语和设置按钮，下方独立的 `openTabsSearch` 负责过滤已打开标签。用户明确拒绝地址栏前缀及复用过滤框，授权自行设计并完成开发。

## Goals / Non-Goals

目标：快捷搜索独立、同词多页面、本地长期保存、结果可完全由用户控制。界面保持原有简洁风格。

非目标：接管 Chrome 地址栏、读取浏览历史、导入全部书签、批量打开页面、修改 Blue 或重做仪表盘。

## Decisions

1. 顶部问候语右侧新增中等宽度输入框，设置按钮前保留间距；窄屏换到第二行。与把输入框塞进过滤区域相比，顶部位置明确区分快捷打开与过滤当前标签。
2. `services/keyword-mappings.js` 管理 `chrome.storage.local.keywordPageMappings`，通过现有 storage service 读写。结构为 `{id, keyword, title, url}[]`；同词可多条，同词同 URL 不重复。使用随机 ID 保持编辑删除目标稳定，写入前重新读取，失败不显示成功、不清空表单。
3. 去除输入前后空格、合并连续空白、忽略大小写。组名搜索保留完整词优先、无完整命中时匹配组名前缀的行为；并始终合并所有分组中页面名称包含输入的映射。单次 filter 保持保存顺序、每条映射只出现一次；不同分组即使关联同一 URL 也保留各自结果。仅匹配用户保存的组名和页面名称，不额外搜索 URL、历史、工具或现有标签。空输入显示使用提示，所有候选可滚动不截断；末尾沿用所属分组标签并提供完整组名悬停提示。
4. `views/keyword-search.js` 负责下拉组合框与原生 dialog 管理弹层；`keyword-search.css` 复用页面主题变量。表单每次添加一个页面，重复填写关键词即扩充同组；列表逐项编辑/删除，提供明确反馈。使用 DOM textContent 防止页面名称或 URL 被当作 HTML。
5. 选择后通过 `chrome.tabs.create({url, active:true})` 新开一个前台标签，保留仪表盘。该主动创建动作不改现有自动标签复用规则。URL 仅允许 HTTP(S)，保留查询参数和片段，不猜测内网页面身份。
6. 组合框支持上下键、Enter、Escape、点击外侧关闭；输入法组合期间不触发打开。管理弹层使用浏览器原生焦点约束并恢复入口焦点。Escape 不触发仪表盘隐私模式。隐私模式隐藏快捷搜索和管理弹层，避免暴露自定义名称/URL。
7. 监听本地存储变化刷新结果和列表，监听现有语言切换事件刷新动态文案。读写失败可重试，不把损坏数据当成空列表覆盖。
8. 管理列表使用原生 `details/summary`：每个关键词一张轻描边卡片，组头展示箭头、名称和页面数，首次加载默认收起。展开状态只在当前仪表盘内记住，列表刷新、编辑删除和重新打开管理弹层不重置；新增/编辑成功自动展开目标组。完整 URL 保留在数据、编辑框和悬停提示中，列表中的名称和 URL 各显示一行并省略超出内容。相较自制 accordion，原生控件自带键盘支持且不需要增加按钮状态和事件模型；不增加“分组套分组”或存储迁移。

## Risks / Trade-offs

- 多个候选不会自动全部打开；直接 Enter 打开当前高亮项（默认第一项），上下键选择其他项。
- 本地映射不跨电脑自动同步；扩展卸载会删除本地数据，与现有本地优先约定一致。
- 组名前缀可能匹配多个自定义词；完整组名命中时不再匹配其他组名前缀，但页面名称包含匹配仍跨组生效。
- 测试仅使用独立 Chrome for Testing 配置，不操作用户工作中的窗口和标签。

## Migration Plan

缺少新 storage key 时视为空映射，无需迁移。旧功能和 manifest 权限不变；重新加载 Xiaoyu 扩展后新打开仪表盘即可使用。

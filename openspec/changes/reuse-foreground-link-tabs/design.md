## Context

现有流程已经覆盖完整 URL 匹配、跨窗口聚焦、关页前复核和通知。缺口只在创建资格：网页链接直接打开新页时，Chrome 的创建事件未提供占位页地址。

隔离 Chrome 的真实点击记录显示：普通 `target="_blank"`、带 `noopener noreferrer` 的链接以及网页调用 `window.open` 时，前台新页有 `openerTabId`，且创建时尚无已提交或挂起地址。对照实验中的 Cmd+点击是后台打开；直接调用 `tabs.create` 和 Chrome 原生会话恢复没有该来源信息。扩展自己的会话恢复也不设置 `openerTabId`。

## Goals / Non-Goals

- 让已开启自动复用的 Xiaoyu 用户通过普通网页点击新开前台标签时，获得与手输网址相同的复用行为。
- 保留前台、通知授权、完整 URL 和先切换后关闭的约束。
- 不改 Blue、权限、设置界面或会话数据格式；后台打开不自动切换或关闭。

## Decisions

- 在现有占位页分支之外，只接纳创建时没有已提交或挂起地址、且 Chrome 提供有效来源标签 ID 的前台新页。后续仍用现有首次加载事件取 URL，不用来源页地址推断。
- 不把所有空地址或直接带 URL 的创建都纳入处理：这些信号不能可靠区分链接、会话恢复及其他来源。也不增加导航观察权限：现有信号已覆盖隔离 Chrome 实测的主要场景。
- 复用现有候选队列、超时和关页前复核。不提前关闭源标签，不修改已有目标的导航。

## Risks / Trade-offs

- `openerTabId` 是 Chrome 提供的来源关系，不是用户手势证明；满足条件的网页脚本前台开页也可触发复用。
- Chrome 没提供来源标签 ID 或已直接提交地址时，仍让新页正常加载。优先避免误关，不猜测浏览器未提供的来源。
- 用真实网页点击、会话恢复和后台打开做隔离浏览器回归；任何误关闭已有页都视为失败。

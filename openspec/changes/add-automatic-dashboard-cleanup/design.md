## Context

当前 `checkTabOutDupes()` 只显示提示，手动按钮调用旧清理逻辑。多个页面各自运行自动关闭会形成竞态，因此本次将关闭行为放到单个 MV3 后台协调器。用户已授权连续开发并自审，不重复等待方案审核。

## Goals / Non-Goals

目标：可开关、默认兼容、保留最新创建的可处理仪表盘、关闭前复核、错误可见。非目标：修改普通网页 URL 防重、Blue、权限、云同步或自动整理其他窗口内容。

## Decisions

1. `dashboardAutoCleanupEnabled` 存在 `chrome.storage.local`，只认严格 `true`，默认关闭。设置在既有“标签页”分区，独立于 `tabReuseEnabled`；开启仅影响后续仪表盘加载，不立即批量操作。
2. 自动合并并入现有 `services/tabs-service.js`，两个开关共享 `views/tab-reuse-settings.js` 的读写逻辑，不新增模块。后台同步注册标签创建/导航/关闭与仪表盘就绪消息；顺序和就绪证明只放当前 worker 内存，不读写会话存储。worker 重启后从再次确认就绪的页面重新协调，不承诺恢复此前创建顺序；通过 `runtime.getContexts({contextTypes: ['TAB']})` 查询仍存活的本扩展顶层 index.html 文档，为旧通用新标签恢复可核验身份。该实时身份仅用于识别候选页，不代替新保留页的就绪消息；接口不可用时保留原有严格证明规则，查询报错则本轮不删除。
3. `dashboard-ready` 消息只接受本扩展 index.html 文档及其真实 sender.tab。先检查普通窗口、非隐身、稳定地址和非置顶。完整本扩展 index.html（可带 query/hash）可识别；通用 chrome/edge 新标签地址须有本扩展页面的就绪证明。其他扩展、Tools、Side Panel 和网页一律不是目标。导航开始会失效旧证明。
4. 就绪请求串行执行。按当前 worker 记录的创建顺序选择最新仪表盘，不把已知老页刷新当作新建。较新页尚未就绪时暂不删除。创建/导航/设置变化中断旧轮清理。逐个删除前重新核验保留页、目标 URL/挂起导航/置顶/窗口；保留页消失则停止，不继续清空所有页。
5. 删除拒绝按单项记录失败，保留该页；存储/查询或身份核验失败时不开始删除。不自动重试有副作用的失败。关键日志只输出 ID、原因和数量，不含 URL 或标题。关闭仅含旧仪表盘的窗口是 Chrome 的自然结果，设置帮助同时提醒未保存输入会丢失、置顶页受保护。
6. 关闭模式保持既有提示；开启隐藏重复提示。自动失败显示简明重试提示，可关闭设置恢复手动处理。页面只发送一次就绪消息，不在每次标签刷新时重新清理。
7. 不采用各页自行关闭或猜测通用新标签归属。显式就绪消息交给同一后台协调；普通网页防重逻辑保持独立。

## Risks / Trade-offs

- 自动关闭会丢失旧仪表盘未保存输入，甚至关闭仅有该页的窗口 → 默认关闭且帮助文案写明，置顶页/隐身页保留。
- 标签创建、导航存在竞态 → 内存顺序、串行协调、就绪证明和删除前复核；不对未知网页猜测归属。不为跨 worker 恢复引入额外持久状态。
- 后台休眠会丢失旧页就绪证明 → 从浏览器实时顶层文档查询恢复身份，仅接受本扩展 index.html；其他扩展和子框架不算证明，不冒险删除未知页面。

## Migration Plan

不迁移旧设置；新开关缺失即关闭。保留原浏览器加载目录与私有配置，仅同步本次运行时补丁，不强制重新加载用户浏览器。开发在公开仓库独立功能分支，验证后按此前授权提交推送该功能分支，不直接推送 main。

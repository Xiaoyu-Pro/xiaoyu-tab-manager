## Context

Dashboard 已通过 `getGreeting()` 按当前小时选择问候语，并通过现有中英文文案表处理语言切换。问候语使用 `textContent` 写入独立标题节点，日期由 `getDateDisplay()` 写入另一个节点。

## Goals / Non-Goals

**Goals:**

- 在所有时间段问候语后稳定展示 `xiao鱼🐟`。
- 中英文使用各自正确的标点和空格。
- 保留现有日期、语言切换和标题样式。

**Non-Goals:**

- 不提供用户可编辑的署名设置。
- 不新增 Logo 图片、动画、颜色或布局。
- 不改变时间段划分和日期格式。

## Decisions

1. 在现有中英文文案表中保存完整署名后缀。这样标点属于语言资源，避免在业务逻辑中判断语言，也方便未来扩展其他语言。
2. `getGreeting()` 先选择时间段文案，再从唯一出口拼接署名。相比在三个分支重复拼接，单一出口更不易漏改。
3. 继续通过 `textContent` 渲染。署名无需富文本，保留文本渲染可以避免 HTML 注入面。
4. 不修改 HTML 与 CSS。署名与问候语属于同一语义和视觉层级，应自然继承现有标题样式。

## Risks / Trade-offs

- [署名固定在代码中，无法由界面编辑] → 这是本次明确范围；未来确有多人使用需求时再引入设置和迁移逻辑。
- [混合中文、拉丁字符与 Emoji 的字体宽度不同] → 保持浏览器原生字体回退，避免为了单个字符引入字体依赖。

## Migration Plan

无需数据迁移。重新加载未打包扩展即可生效；回滚时恢复两处语言资源和 `getGreeting()` 即可。

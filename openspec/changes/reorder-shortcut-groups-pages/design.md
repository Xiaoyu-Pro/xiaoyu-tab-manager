## Context

快捷分组由 `keywordPageMappings` 数组按首次出现的关键词生成，组内页面也沿用数组顺序。映射服务已有跨页写锁，页面已有实时重绘与提示；用户授权连续完成、自审，不逐项确认。

## Goals / Non-Goals

目标：分组及同组页面可拖动排序，松手自动本地保存，刷新、管理、搜索和备份保持顺序；取消、失败及并发不丢映射。
非目标：跨组移动、真实 Chrome 标签或窗口重排、触屏专用拖拽、多层分组、新备份格式或 Blue 修改。

## Decisions

1. 使用既有映射数组保存排序，优于新增分组顺序/页面顺序配置键；不迁移数据。分组排序将当前各组按新顺序展平，组内次序不变；页面排序只替换该组占用的数组位置，其他组不变。重命名保留顺序，新增映射仍追加，备份沿用原格式与数组顺序。
2. 映射服务增加明确的分组/页面相对移动接口，在现有写锁内读最新数据并单次写入。未知源、未知目标、跨组页面或无效位置拒绝，不猜测或重建丢失记录；同位置不写入。排序不读取或写入颜色键。
3. 复用浏览器原生拖拽事件及当前 UI 控制器，不新增模块/库。标题旁及每行左侧增加小拖拽柄；页面打开按钮保留为独立按钮，不嵌套交互元素。多列卡片以目标左右半区、单列和页面以目标上下半区决定前后，显示淡雅落点标记。
4. 拖动只接受本页面产生的内部状态，不读取外部拖入载荷；写入成功后再刷新卡片，不先改 DOM。失败提示且保留旧顺序，拖动取消无写入；键盘柄支持 Alt+上下键，以同一存储接口排序。
5. 拖拽与保存期间推迟仪表盘实时重绘，异步快照写入前再次检查；结束后处理被合并的刷新。键盘重绘保留相同柄的焦点；切换视图、隐私模式或拖拽结束清理临时状态。

## Risks / Trade-offs

- 页面仍在后台加载，事件重绘打断拖拽 → 在调度及真正写入 DOM 的异步边界检查排序状态，结束时补刷新。
- 其他仪表盘改动了映射 → 锁内读最新数组、稳定 ID 或规范关键词定位，只做相对移动；失效则拒绝，不覆盖或丢掉新条目。
- 同一数据源影响搜索顺序 → 明确三个入口统一顺序，内容匹配及完整 URL 不改变。
- 普通点击与拖拽混淆 → 独立柄启动，真实浏览器验证不新建或激活页面；不在整行按钮上开启 draggable。

## Migration Plan

从当前 main `f72ea7d` 创建 `yzh/feat/shortcut-drag-order`，保留先前修复。验证后增量同步原加载目录，核对 Blue 和配置未变；按既有授权提交推送功能分支，不合并 main。用户自行重新加载扩展；只在隔离 Chrome 中操作测试数据。

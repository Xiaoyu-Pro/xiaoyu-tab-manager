## Context

隔离 Chrome for Testing 上，macOS 从外部打开 HTTP(S) 链接时，已有普通窗口收到前台新标签，带有效 `openerTabId` 和 `pendingUrl`，尚无已提交 `url`。手动复制的创建事件一开始已有已提交地址。Chrome 原生恢复同样可带已提交地址；Xiaoyu 在已有窗口恢复使用不带来源的 `tabs.create`。批量新窗口恢复中后续新页可能有来源和待加载地址，但实测 `windows.onCreated` 先于标签创建事件。

## Goals / Non-Goals

- 覆盖 Codex 等桌面应用在已有普通前台窗口内打开的同址链接；复制标签和会话恢复保留。
- 不引入权限，不识别具体来源应用，不更改 Blue 或其他打开方式。

## Decisions

- 原路径不变；只新增“无已提交地址、创建时已有 HTTP(S) 待加载地址、具有有效来源”的入口。需要来源标签仍在同一窗口且已稳定加载。
- 通过 Chrome 已有窗口创建事件标记新窗口，拒绝该入口处理窗口创建后两秒内的标签。批量恢复即使后续标签有来源也不参与。窗口短期标记保留在内存，不保存 URL。
- 不接受创建时已有已提交网页地址的标签，因此 Chrome 的「复制标签页」不进入匹配。待加载地址也不在创建事件直接执行关闭，仍由既有首次加载和切换复核完成。

## Risks / Trade-offs

- Chrome 不提供外部应用身份；判定是基于可观察事件。新窗口刚建、来源不明或尚未稳定时宁可保留。
- 不将两秒放宽到持续接管，也不对过去已有的重复标签做批量关闭。

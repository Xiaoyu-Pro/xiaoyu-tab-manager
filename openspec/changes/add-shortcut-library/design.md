## Context

现有映射为 `keywordPageMappings` 下的 `{id, keyword, title, url}[]`，搜索框、折叠管理和跨组名称匹配已经可用。现有 `focusTab(url)` 有同域名兜底，不能用于新快捷入口。用户明确授权全量实现并由代理自审，延续现有轻量风格。

## Goals / Non-Goals

目标：用同一份映射打通收录、搜索、分组卡片、精确打开、显式副本与迁移备份。

非目标：云同步、全量书签/历史导入、自动抓取内网页面、改写登录态、按名称或域名推断同页、改变 Blue 和既有自动防重策略。

## Decisions

1. 新入口中文名“快捷”、英文 Shortcuts，内部值 `shortcuts`。沿用主导航和 mission-card 风格，每张卡片为一个映射组。卡片来源为持久映射而非当前打开的标签，因此关闭网页不会让入口消失。该视图隐藏原“过滤标签页”但保留其值；顶部快捷搜索仍可用。
2. 给现有记录增加可选 `aliases: string[]`，旧数据读取为 `[]`，写入时统一规范化。别名每行一个、去除多余空白和重复项，参与跨组包含匹配；所有展示经转义。组名匹配优先规则保持，命中多项不重复展示。
3. 新建 `services/shortcut-tabs.js`，集中实现普通窗口快照、完整 URL 目标选择、复用与新副本。目标必须非隐身、完整已提交 URL 一致且没有挂起其他导航；优先当前窗口、再最近使用，允许激活已有置顶/休眠页，不做关闭。点击前重新获取快照并核实目标；目标导航或操作失败时明确报错，不跳到同域名别页、不盲目新建。显式副本直接以完整 URL 调用 tabs.create，不设置 opener；不改变全局自动防重规则。
4. 状态快照同时供搜索和快捷卡片显示“已打开 · 窗口 N”，监听标签变动刷新。只持有内存状态，不把浏览器标签身份导出。无匹配则新建前台标签；失败不得宣称成功。复用与显式副本均保留仪表盘及所有既有页面。
5. 右键使用扩展页面内的轻量菜单，只有“新开副本”动作，并支持 Escape/键盘访问；不申请 contextMenus 权限。搜索还支持 Shift+Enter 新副本。公共打开逻辑保证所有入口行为一致。
6. 管理 UI 提供别名 textarea 和导入/导出操作。现有标签行追加“加入快捷搜索”按钮，打开同一管理表单并填入真实标签标题/URL；用户选择组后保存，不直接批量收录或修改页面。
7. 备份格式为 `{format:'xiaoyu-tab-manager-shortcuts', version:1, exportedAt, mappings:[{keyword,title,url,aliases}]}`，不导出内部 ID 或浏览器窗口。限制导入 2 MiB / 5000 条以控制解析和列表成本；任一无效条目、版本或格式都拒绝整个文件。导入先预览新增/既有/别名更新数，确认后在现有 Web Lock 内重新读取并一次提交。重复的规范化组名+完整 URL 保留本机记录与 ID，仅合并别名；新增记录生成新 ID。导入失败无部分落地，重复导入幂等。导出用本地 Blob 下载，无需 downloads 权限。
8. 替代方案：单独复制一套收藏页会产生两份数据；直接复用旧 focusTab 会按域名误跳；直接覆盖导入会破坏用户已有配置，均不采用。纯渲染器 `shortcut-library-view.js` 与共享控制器配合，业务和安全逻辑放在服务而非卡片模板。

## Risks / Trade-offs

- 内网 URL 可能含敏感参数 → 备份仅本机文件，管理页明确提示，不上传远端或公开仓库。
- 公司链接存在转发 → 本功能只按最终可验证的完整 URL 精确匹配，不猜测别名或重定向等价；全局初始加载防重维持原状。
- 状态显示与点击之间页面关闭/变址 → 点击重新查询及验证，失败后刷新状态并提示，绝不删除其他标签。
- 增加第四 Tab 会影响导航偏好和测试白名单 → 同步两个导航白名单、偏好解析、渲染分支和测试；旧值及原工作子视图不变。
- 保存数据增量 → 旧记录无须迁移；验证坏 aliases 不会静默清空已有数据。导入预览与确认间数据变化由确认时重新合并处理。

## Migration Plan

旧记录按空别名读取，无需批量重写。重新加载 Xiaoyu 和仪表盘后生效，导航偏好可以保存 shortcuts。不修改权限、后台和 Blue；提交和发布不在授权范围。使用独立 Chrome for Testing 验证，不操作用户工作中的浏览器。

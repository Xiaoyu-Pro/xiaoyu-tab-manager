## Context

当前仓库是从 Super Tab Out 继续开发的 Chrome Manifest V3 扩展，用户已经在本地使用 `super-tab-out-*` 存储键、事件名和 Web Lock 名称保存偏好、工作分组与窗口组织数据。产品准备以 “Xiaoyu Tab Manager” 对外展示，并可能公开或商业分发，因此改名同时涉及品牌一致性、升级兼容、上游署名和安装包完整性。

当前打包脚本使用一份手写文件清单，但没有包含新增的工作/窗口视图模块，也没有把根目录的 `LICENSE`、`NOTICE` 带入 ZIP。继续分散维护文件清单会让源码可用、发布包不可用的问题反复出现。

## Goals / Non-Goals

**Goals:**

- 所有当前用户可见入口统一显示 “Xiaoyu Tab Manager”。
- 已安装版本升级后继续读取现有本地数据，不执行无意义的存储迁移。
- 明确区分产品品牌、内部兼容标识和上游作品署名。
- 发布包包含完整运行时依赖与许可证文件，并能被自动验证。
- 不增加依赖、浏览器权限或远程服务。

**Non-Goals:**

- 不改 GitHub 仓库名、源码目录名或历史提交。
- 不重命名 `super-tab-out-*` storage key、DOM event、Web Lock 和现有 JavaScript 全局对象。
- 不在本次设计新 Logo、注册商标或代替专业律师给出法律意见。
- 不改写历史 CHANGELOG 中用于说明来源或旧版本行为的必要名称。

## Decisions

### 1. 对外品牌与内部契约分层

扩展名称、页面标题、页面内品牌、Omnibox、导出文件名、README 和商店文案使用 “Xiaoyu Tab Manager”。内部 `super-tab-out-*` 标识保持不变，因为它们是升级兼容契约，不属于用户可见品牌。

没有采用全仓库机械替换：它会破坏已有存储数据，并错误抹去上游项目的法定署名。

### 2. 署名采用“当前产品 + 明确上游”结构

`NOTICE` 首先声明 Xiaoyu Tab Manager 及其修改，再完整保留 Super Tab Out、Tab Out 和 QR Code generator 的来源与许可。页面页脚以当前产品仓库为主链接，同时给出 “Based on Super Tab Out and Tab Out” 的简短归属。

根目录新增集中修改清单，用于记录不可写注释的 JSON、图片和文档改动；可注释的核心源文件保留或补充衍生修改声明。`LICENSE` 正文不改动。

### 3. 打包文件清单单一来源

新增一个无副作用的打包清单模块，由打包脚本和验证脚本共同导入。清单显式列出扩展运行时文件与根目录法律文件，避免两份列表漂移。

打包时复制清单文件到系统临时目录，以扩展根为 ZIP 根目录，再复制 `LICENSE`、`NOTICE` 和修改清单。临时目录使用固定前缀创建并在 `finally` 中校验边界后清理，避免把 `extension/` 目录层级或 `../` 路径写入 ZIP。

### 4. 验证运行时闭包而非只验证几个文件名

验证脚本检查：清单中的源文件存在；Manifest 引用存在；HTML 的本地 `script[src]`、`link[href]` 引用存在且已被打包；后台 `importScripts` 引用存在且已被打包；ZIP 根目录有 Manifest 和法律文件；旧品牌只在兼容标识、上游署名和历史语境中出现。

浏览器级验证继续使用隔离的临时 Chrome 配置加载未打包目录和最终 ZIP 解压目录，覆盖 Dashboard、Side Panel、Tools 及后台脚本。

### 5. 包名属于发布产物，不属于兼容契约

产物统一为 `xiaoyu-tab-manager-{chrome|edge}-<version>.zip`。旧 ZIP 名不需要兼容；浏览器扩展身份由签名/商店 ID 决定，而不是本地 ZIP 文件名。

## Risks / Trade-offs

- **商标风险**：初步检索没有发现明显同名项目，但不能等同于商标清查。缓解方式是公开发布前检索目标市场并保留更名能力。
- **许可说明不充分**：只改品牌会让使用者误以为是完全原创。通过 NOTICE、修改清单和页脚署名降低风险。
- **内部旧名称仍可被开发者看到**：这是有意保留的兼容层。相比迁移所有 key 和事件，它的维护成本更低、数据风险更小。
- **显式清单需要维护**：它比自动收集更可审计。通过共享模块与引用闭包验证降低漏项概率。
- **临时目录清理失误**：严格验证目录前缀，只清理本次创建的目录，并在异常时由操作系统临时目录兜底回收。

## Migration Plan

1. 先增加品牌与打包契约测试，确认当前代码会失败。
2. 更新产品文案、说明和署名，不改内部兼容标识。
3. 抽取共享清单，修复 Chrome/Edge 打包与验证。
4. 运行单元测试、静态验证和双目标打包验证。
5. 在隔离 Chrome 配置中加载并检查页面，不触碰用户正在使用的浏览器窗口和数据。
6. 若需要回滚，只回滚用户可见品牌和打包脚本；存储 schema 未变化，无需数据回滚。

## Open Questions

- GitHub 仓库 slug 是否未来从 `super-tab-out` 改名；本次不处理，以避免外部链接和远端仓库发生额外变化。

## Context

分组来自映射的 keyword，现有服务已用 Web Lock 协调跨页面写入。用户已确认 HEX/RGB 并要求直接开始，追加快捷组名旁的小色标。

## Goals / Non-Goals

目标：淡雅标签、分组自定义色、同色标题标记与持久化。非目标：页面方块改版、修改映射身份/打开行为、颜色云同步、修改 Blue 或扩展备份格式。

## Decisions

1. 在现有映射服务增加颜色解析、默认配色、文字对比色与颜色读写。`keywordGroupColors` 保存规范化组名到 `#RRGGBB` 的对象，复用现有写锁；不将相同颜色重复写入各页面，不改旧记录。
2. 接受 `#RGB`、`#RRGGBB` 和 `rgb(r, g, b)`，RGB 仅整数 0–255。拒绝透明色、任意 CSS 和未知格式；保存为大写六位 HEX。对象键使用自有属性访问，颜色值只由校验器产生。
3. 未配置时从固定淡雅色板按组名计算稳定默认色，背景使用所选色本身，标签文字按相对亮度选择黑/白以保证至少 4.5:1。用户自选颜色不被二次改写成另一种色值。
4. 管理组头增加颜色按钮，使用同一内联小表单提供原生选色、HEX/RGB 输入、保存/恢复默认/关闭。存储失败保留输入；损坏配色不覆盖，管理提示错误，但原映射仍可搜索和打开。
5. 搜索组名显示圆角色块；快捷卡片的组名文字后仅放小圆角方块，保持组名、页面数和链接列表不变。颜色变化通过现有存储事件刷新两处，不动 Blue。
6. 颜色是本机显示偏好，不混入既有映射备份；旧导入、导出、损坏映射保护和精确 URL 规则保留。所有控件支持双语、键盘、主题与隐私模式。

## Risks / Trade-offs

- 用户输入 CSS 或越界 RGB → 严格解析后再进入 DOM/CSS，测试恶意输入与原型同名组。
- 自定义深色导致文字不清 → 黑白文字自动选择，明暗主题测试实际对比度。
- 颜色读取失败 → 单独报告并禁用颜色编辑，不覆盖坏数据，不清空映射。
- 新偏好不随当前备份迁移 → 保持已发布备份契约，后续若需要再单独扩展。

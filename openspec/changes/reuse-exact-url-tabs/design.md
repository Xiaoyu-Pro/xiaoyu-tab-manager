## Context

Blue Tab Manager 与 Xiaoyu 原版已有手动查重、跨窗口聚焦和按 `tabId` 关闭的能力。自动复用必须在后台响应浏览器事件，且不能调用找不到精确 URL 时可能按域名回退的 `focusTab(url)`。第一阶段在 Blue 完成；用户确认后，将相同行为移植到 Xiaoyu，保留现有手动查重语义及两个版本的独立品牌。

## Goals / Non-Goals

**Goals:**

- 开启功能后，尽早识别前台新标签页的首次网页加载，并复用同一浏览器个人资料内的完全相同网址。
- 确认已有页及窗口激活后，只关闭仍符合条件的新标签，并发送准确结果提醒。
- 将自动关闭设为明确启用的行为；对不确定的导航或状态变化保留新页。

**Non-Goals:**

- 不合并旧标签，不处理旧页内导航、刷新、前进后退、后台打开、隐身窗口或跨 Chrome 个人资料。
- 不做 URL 规范化、重排参数、去除片段、同域名匹配或重定向目标预测。
- 不注入网页脚本，不拦截网络请求，不保证网页请求还没发出。

## Decisions

### 1. 采用一次开启、自动复用的交互

可选做法是每次弹出通知让用户点击确认，能保留手动选择但会增加一次操作；也可以只高亮工具栏，权限更少但提醒较不明显。本次采用设置中主动开启后自动完成操作，并发送系统通知。设置提示“只关闭前台刚打开的重复页”，保持默认关闭，不改动原有工具栏计数。

在 `optional_permissions` 声明 `notifications`，从设置开关的用户操作申请权限。拒绝、撤销或浏览器报告通知被禁用时不自动关闭；显示可理解的设置状态。通知使用本地扩展图标和现有语言文案，不包含标题、网址或查询参数。开启状态只存本地。参见 [Chrome 通知 API](https://developer.chrome.com/docs/extensions/reference/api/notifications) 和 [可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions#implement-optional-permissions)。

### 2. 仅跟踪可识别的首次前台加载

由后台服务在 `tabs.onCreated` 建立新页资格，只接收已经报告明确占位地址的前台标签（空白页、浏览器或本扩展的新标签页）；仅空地址或创建时已挂起网页 URL 不足以证明来源。隔离 Chrome 验证发现，直接打开网址与批量会话恢复都可能报告空 `url` 和 HTTP(S) `pendingUrl`，因此本版只支持先打开占位页再加载网址。在 `tabs.onUpdated` 看到其首个 HTTP(S) 加载时检查一次；优先读 `pendingUrl`，无该字段时只接受首次提交且还处于加载中的 `url`。Chrome 不保证能在导航提交前观测到挂起 URL。[Chrome 标签页事件与字段](https://developer.chrome.com/docs/extensions/reference/api/tabs)

资格按 `tabId` 短期记录于 `storage.session`，只存必要的 ID、时刻和处理状态，以覆盖服务工作线程休眠；创建后 2 分钟仍未开始导航则失效。在首个符合条件的加载事件消费资格，单次处理限于该事件后 2 秒；超时、关闭、移动到另一窗口、明显后续导航或变为置顶/分组均放弃。网址只在当次调用内存中比较。启动恢复、已提交网页的恢复标签和扩展自己发起的会话恢复不接管；若浏览器事件无法可靠区分来源，收窄该入口的自动触发范围。后台创建后才激活的页不补做自动切换。

### 3. 只按完整浏览器 URL 和已存在的 tabId 操作

直接比较 `pendingUrl` 或首次 `url` 与已有页已提交的 `url` 字符串；协议、路径、查询参数顺序和 `#` 都参与比较。已有页必须是同一浏览器个人资料下非隐身普通窗口中仍存在的标签；排除正在处理的其它新页、已卸载需重新加载的页、正在导航到别处的页。多个合格页优先同窗口，其次最近活跃；无法区分时用稳定的 `tabId` 次序。已有页即使置顶也可以作为切换目标，不更改其置顶或分组。

处理串行化，重复事件按一次处理。先重查设置、权限、源标签当前是否在前台及目标状态，再以 `tabs.update` 激活目标标签、必要时恢复并聚焦目标窗口。确认窗口与目标标签确实激活；移除前重新核对两端仍是预期 URL 和窗口、源标签仍属这次短期首次加载且未被保护。只调用 `tabs.remove(newTabId)`，绝不按 URL 批量删除。若切换后不能安全关闭，保留新标签；成功通知只在关闭成功后发出。失败按阶段记录结果，不记录 URL、不自动重试。

## Risks / Trade-offs

- 浏览器没有“匹配、聚焦、关闭”的原子操作。用短处理期限、最终状态复查和精确 ID 缩小竞态窗口；跳转失败或无法确认状态时保留新页。
- 快速加载或恢复事件可能缺少可靠信号。保守漏接管优先于误关；以隔离 Chrome 的慢响应与快速页面覆盖真实事件顺序，并检查旧页导航、前后台和会话恢复。
- 系统勿扰等设置可能隐藏已发送的通知。浏览器报告权限不可用时暂停自动处理；操作完成后通知投递失败不重新执行关页。

## Migration Plan

保持既有数据和手动操作。两个独立扩展各自默认关闭新设置，不互相迁移授权或开关。Xiaoyu 移植版使用 `1.0.10` 生成新包，保留旧包和 Blue 发布产物。用户关闭开关后即时停止新的自动处理并使待处理资格失效。

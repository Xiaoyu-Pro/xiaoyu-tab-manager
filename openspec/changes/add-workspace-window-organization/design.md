## Context

Super Tab Out 当前 Dashboard 的打开标签页区有“按域名”和仅在存在原生标签组时出现的“按 Chrome 标签组”两种展示。域名能描述站点，却不能描述用户正在完成的工作；Chrome 窗口则是真实运行容器，页面分散后没有跨窗口的可视化编排入口。

本变更面向同一 Chrome profile 下的多个普通窗口。用户希望三个一级入口像 Tab 一样切换，工作编排长期保存，窗口拖拽立即作用于浏览器，并且两类操作都能撤销。扩展现有代码采用无构建步骤的 IIFE 模块和 Node `assert` 测试；新实现必须延续该形态、现有视觉令牌与隐私边界。

## Goals / Non-Goals

**Goals:**

- 固定提供“域名 / 工作 / 窗口”三个一级视图，并在工作内提供“工作编排 / Chrome 标签组”。
- 建立独立、版本化、可迁移的工作模型，支持 CRUD、精确页面匹配、待整理和长期保存。
- 明确分离逻辑组织与真实 Chrome 状态：工作拖拽只改归属，窗口拖拽立即移动。
- 以最少标签移动数为目标把非空工作一一映射到现有窗口，不足时才创建新窗口。
- 将单工作“创建标签组”扩展为移动到合适窗口后再创建或安全复用原生组。
- 对逻辑移动和真实移动都提供最近一次撤销，并处理实时 Chrome 事件、关闭标签和部分失败。
- 沿用现有布局、颜色、字体、按钮、圆角、阴影、favicon 安全策略和中英文能力。

**Non-Goals:**

- 不支持跨 Chrome profile、跨设备或跨浏览器同步。
- 不把工作组织上传到服务器，不引入账号或协作能力。
- 不自动猜测“同域名即同工作”之外的语义关系；首次快照后只使用用户操作和精确页面匹配。
- 不移动置顶标签、隐身窗口、扩展内部页或非 `normal` 窗口。
- 不提供多层级工作、标签、智能推荐或长期操作历史；本期只保留一次撤销。

## Decisions

### 1. 三层职责而不是继续堆叠 `app.js`

采用“模型与规划器 / Chrome 操作协调器 / 纯视图渲染器”三层结构：

- `workspace-service.js` 管持久化和归属，不访问 DOM。
- `workspace-planner.js` 只接收快照并返回计划，不访问 Chrome API 或 storage。
- `workspace-operations.js` 串行执行计划、重校验和撤销，不生成 HTML。
- `views/*.js` 只接收 ViewModel 并输出安全 HTML。
- `app.js` 负责路由、事件、文案和服务编排。

相比把功能全部写入现有四千多行的 `app.js`，这一结构的一次性文件成本更高，但能独立测试关键算法，也避免真实移动、持久化和渲染互相污染。相比引入 React/Vue，延续 IIFE 无构建结构能保持扩展部署方式和依赖面不变。

### 2. 长期归属使用精确 URL 散列，会话归属使用 tabId

`chrome.storage.local.workspaceState` 使用以下版本化结构：

```js
{
  schemaVersion: 1,
  initializedAt: 0,
  workspaces: [{ id, name, createdAt, updatedAt, order }],
  pageAssignments: { [sha256(normalizedUrl)]: workspaceId }
}
```

`normalizedUrl` 保留 scheme、host、path 和 query，仅移除 fragment；长期只保存 SHA-256 键，不保存明文 URL。`chrome.storage.session.workspaceSession` 保存 `{ tabAssignments, undoEntry }`，其中 `tabAssignments[tabId]` 优先于长期键。

选择精确页面匹配而不是域名推断，是为了避免三个工作共用 WPS、飞书或内部工具域名时被错误合并。选择散列而不是明文，是为了降低长期存储直接暴露浏览路径和查询参数的风险。

同一精确 URL 在同一会话可借助不同 `tabId` 分属不同工作；浏览器重启后无法稳定区分两个完全相同的 URL，最后一次长期归属会成为共同默认值。这是浏览器标签缺少稳定跨会话实例 ID 的固有限制，UI 不承诺重启后保留重复 URL 的不同归属。

### 3. 首次快照一次，后续新页面进入待整理

首次进入“工作编排”且 `workspaceState` 未初始化时，将当前域名卡片复制为初始工作，名称使用现有域名显示名并保证唯一。之后不再自动创建工作；没有会话归属和长期散列归属的页面进入“待整理”，待整理内部按域名聚合。

这既满足“初始视图沿用原有聚合、支持拖拽”的低迁移成本，又防止每次打开新域名都永久污染工作列表。工作名去空格后必须非空，并按不区分大小写的规则唯一。

### 4. 工作拖拽是逻辑写入，窗口拖拽是串行 Chrome 操作

工作拖拽调用 `assignTab(tab, workspaceId)`，同时更新会话归属和长期页面归属，不调用 `chrome.tabs.move`。写入前保存该标签的旧归属，通过现有 Toast action 提供一次撤销。

窗口拖拽先通过 `workspace-operations.js` 获取 `{ tabId, windowId, index, groupId }` 快照，再调用 `chrome.tabs.move`，完成后将快照写入 `storage.session`。撤销重新查询仍存在的标签并尽力恢复窗口、顺序和可恢复的分组；已关闭或目标窗口已消失时返回跳过数量，不能假报完全恢复。

所有真实 Chrome 操作通过单一 operation lock 串行；支持 Web Locks 时，该锁覆盖同源的多个 Dashboard 页面，否则退化为当前页面内锁。工作模型的 read-modify-write 同样使用独立同源锁，避免多个窗口同时打开 Dashboard 时互相覆盖长期归属或撤销快照。Chrome 事件在拖拽或操作期间只设置一个“待刷新”标志，结束后合并刷新一次，防止 DOM 在投放中被替换，也防止 API 事件与本地乐观更新交错。

### 5. 使用最大权匹配保证最低移动数

对每个非空工作和每个普通窗口计算重叠标签数 `overlap[workspace][window]`。求工作与窗口的一一最大权匹配，最大化留在原窗口的标签数量，等价于最小化移动数。规划器使用 O(n³) 匈牙利算法；数量不足的一侧使用虚拟节点补齐。匹配到虚拟窗口的工作用该工作的一枚现有标签执行 `windows.create({ tabId })`，再移动剩余标签。

逐工作选择当前重叠最多窗口的贪心方案会因争用同一窗口产生非全局最优结果，因此不采用。规划结果包含 `assignments`、`moves`、`groupMoves`、`newWindows`、`splitGroups`、`excludedTabs` 和 `summary`，执行前由用户确认摘要。

### 6. 原生标签组仅按成员状态复用，不按标题复用

如果一个工作的全部可操作标签当前共享同一有效 `groupId`，则移动整个组并更新其标题；否则在聚合到目标窗口后新建组。绝不只凭标题相同复用原生组，因为用户可能拥有同名但语义不同的组。

跨窗口移动完整且纯净的原生组时优先使用 `tabGroups.move`；如果组内混有其他工作的标签，则按 tab 移动并在摘要中计为 `splitGroups`。置顶标签始终排除，不为了成组而改变 pinned 状态。

### 7. 视图入口始终可发现，并复用既有视觉语言

一级导航始终出现。“Chrome 标签组”移动到“工作”的二级导航，即使数量为零也显示空状态，不再强制回域名视图。导航状态使用现有页面偏好存储；工作状态使用 `chrome.storage`。

新卡片复用现有 CSS 变量、`action-btn`、favicon 组件、8px-10px 圆角和阴影。拖拽同时提供键盘“移动到…”菜单，所有 tab 与按钮带正确的 `role`、`aria-selected`、`aria-label` 和 `:focus-visible`。减少动画偏好下不使用位移动画。

### 8. 虚拟“新窗口”是永久投放目标，不是持久化窗口草稿

`window-view.js` 在真实窗口卡片之后始终追加且只追加一个虚拟“新窗口”卡片，使用保留目标 ID `window:new`。该卡片没有 `windowId`，不进入 `organizationWindows`，也不计入窗口数量；即使没有任何可管理的真实窗口，它仍作为唯一可操作入口显示。

拖拽控制器继续只传递 `{ tabId, sourceId, targetId }`。`app.js` 在把 `window:*` 解析成数字前先识别 `window:new`，并调用独立的 `moveTabToNewWindow(tabId)` 编排函数。该函数复用现有操作协调器的 `executeWindowPlan({ newWindows: [{ seedTabId, remainingTabIds: [] }] })`，因此执行前重校验、operation lock、最小撤销快照、失败补偿和真实结果提示与批量重排保持同一语义，不新增第二套创建窗口流程。

`tabs-service.js` 继续通过 `windows.create({ tabId, type: 'normal', focused: false })` 创建真实窗口，明确不抢夺当前焦点。创建成功并刷新后，新窗口按普通卡片展示，而虚拟卡片仍位于末尾。键盘“移动到…”目标列表使用内部哨兵值表示“新窗口”，最终调用同一个 `moveTabToNewWindow`，不模拟拖拽事件。

撤销只恢复本次标签的原窗口、索引和分组，不显式调用 `windows.remove`。这样当新窗口后来加入其他标签时，撤销不会误关窗口或带走无关标签；若移走最后一个标签后 Chrome 自动结束空窗口，则遵循浏览器自身生命周期。

### 9. 单行关闭以 tabId 为事实，不以 URL 推断实例

“域名 / 工作 / 窗口 / Chrome 标签组”中的单行关闭按钮统一携带 `tabId`，由 `app.js` 事件委托调用 `tabs-service.js` 的 `closeTabsByIds([tabId])`。服务在执行前重查现存标签并排除置顶标签，返回实际关闭的 ID；目标已经消失或已受保护时，UI 只能提示未关闭，不能误报成功。

成功关闭后从 Chrome 重新获取完整快照并重渲染当前视图，不再只删除当前 DOM 节点。这样标签计数、卡片存亡、窗口列表与工作会话归属都由同一个浏览器事实更新，也避免相同 URL 在不同窗口或工作中被一起关闭。批量关闭和“稍后阅读后关闭”继续保持各自既有的 URL 集合语义，本决策只约束用户点击某一真实标签行时的单实例操作。

## Risks / Trade-offs

- [Chrome API 操作期间标签被关闭或窗口消失] → 执行前重查，逐步记录成功项，结构化报告跳过/失败并尽力补偿。
- [实时事件导致拖拽目标 DOM 失效] → 拖拽和 operation lock 期间合并刷新，结束后只补一次。
- [完全相同 URL 跨重启无法区分归属] → 会话内以 tabId 区分；长期语义明确为页面默认工作，并在文档说明限制。
- [SHA-256 不是匿名化，低熵 URL 可被枚举] → 不上传、不记录明文、不记录会话 URL；隐私说明如实描述本地散列而非声称不可逆匿名。
- [自动重排可能打断正在工作的窗口布局] → 默认只规划不执行，确认摘要后执行；排除置顶/隐身/内部页并提供一次撤销。
- [窗口数较多时算法或 DOM 变慢] → 匈牙利算法 O(n³) 对用户级窗口数量足够；渲染按窗口/工作一次构建并使用事件委托。
- [旧 `domain/group` 视图偏好不兼容] → 一次迁移到新的 `organizationView/workspaceSubview`；无法识别的值回退到 `domain`。
- [用户快速连续投放导致重复创建] → 虚拟目标复用既有 operation lock；操作完成前拒绝第二个真实窗口编排，不做乐观重复创建。
- [撤销时新窗口已加入其他标签] → 撤销仅移动快照内标签且不主动关闭窗口，确保后来加入的标签保持原位。
- [相同 URL 存在多个实例] → 单行按钮只提交当前行的 `tabId`；域名视图的重复计数在重新渲染后递减，不扩散到其他实例。
- [点击关闭时标签已消失或变为置顶] → 服务返回空结果，界面刷新真实状态并提示未关闭，不做乐观删除。

## Migration Plan

1. 新模块先以纯函数和 fake Chrome/storage 测试落地，不改 UI。
2. 加载脚本并接入三级导航；默认仍为域名，确保稳定行为不变。
3. 首次访问工作视图时延迟创建 `workspaceState`，避免升级即写入用户存储。
4. 接入逻辑拖拽、真实窗口拖拽、永久虚拟新窗口目标、创建组与全局重排，逐项验证后台创建、撤销和部分失败。
5. 更新隐私说明和中英文 README，运行全量测试、扩展静态校验、隔离浏览器 QA 和代码 Review。

回滚时可移除新增脚本和导航路由；既有域名视图、收藏与会话数据不依赖新模型。遗留的 `workspaceState/workspaceSession` 键不会影响旧版本，可在后续明确的数据清理功能中由用户选择删除，不在回滚时自动破坏数据。

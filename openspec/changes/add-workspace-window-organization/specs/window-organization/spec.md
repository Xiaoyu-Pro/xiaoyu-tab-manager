## ADDED Requirements

### Requirement: 窗口视图反映当前普通 Chrome 窗口
系统 SHALL 展示当前 Chrome profile 中每个非隐身 `normal` 窗口及其可操作标签，并 MUST NOT 按 URL 去重真实标签实例。

#### Scenario: 两个窗口包含相同 URL
- **WHEN** 两个当前标签具有相同 URL 但不同 `tabId` 或 `windowId`
- **THEN** 窗口视图分别展示两个真实标签实例

#### Scenario: 查询到隐身或非普通窗口
- **WHEN** Chrome 返回隐身、popup、panel 或其他非 `normal` 窗口
- **THEN** 系统不把这些窗口和标签纳入窗口编排

#### Scenario: 窗口包含置顶标签
- **WHEN** 普通窗口存在置顶标签
- **THEN** 系统显示置顶标签数量但不允许拖拽或自动移动这些标签

### Requirement: 窗口视图始终提供虚拟新窗口目标
系统 SHALL 在窗口视图末尾始终且仅展示一个虚拟“新窗口”投放目标；该目标 MUST NOT 具有真实 `windowId`、写入持久化状态或计入普通窗口数量。系统 SHALL 支持通过拖拽和键盘入口把一个可操作标签移动到由该目标创建的后台普通窗口。

#### Scenario: 存在多个真实窗口
- **WHEN** 窗口视图展示一个或多个普通窗口
- **THEN** 系统在所有真实窗口卡片之后额外展示且只展示一个虚拟“新窗口”目标，并保持真实窗口计数不变

#### Scenario: 不存在可管理的真实窗口
- **WHEN** 当前没有可展示的非隐身 `normal` 窗口
- **THEN** 系统仍展示虚拟“新窗口”目标，而不是只展示不可操作的空状态

#### Scenario: 拖拽标签到虚拟目标
- **WHEN** 用户把执行前仍可移动的标签投放到虚拟“新窗口”目标
- **THEN** 系统使用该标签在后台创建一个不抢夺焦点的真实普通窗口，刷新后展示新窗口，并继续保留一个虚拟目标

#### Scenario: 通过键盘选择新窗口
- **WHEN** 键盘用户在标签的“移动到”入口选择“新窗口”
- **THEN** 系统调用与拖拽相同的创建、重校验、撤销和提示流程

#### Scenario: 标签在创建前失效
- **WHEN** 标签在执行前已经关闭、被置顶、进入隐身或非普通窗口，或导航到受保护页面
- **THEN** 系统不创建窗口，并报告标签已经无法移动

#### Scenario: 连续创建多个窗口
- **WHEN** 用户在前一次操作完成后再次把标签投放到虚拟目标
- **THEN** 系统为本次标签创建另一个真实窗口，同时虚拟目标数量仍为一个

#### Scenario: 撤销后新窗口已有其他标签
- **WHEN** 用户创建新窗口后又加入其他标签，再撤销最初的创建移动
- **THEN** 系统只恢复撤销快照中的标签，不主动关闭包含其他标签的新窗口

### Requirement: 跨窗口拖拽立即移动真实标签并可撤销
系统 SHALL 在用户把可操作标签投放到另一个窗口时调用 Chrome API 立即移动该标签，并 SHALL 为最近一次成功移动提供一次撤销。

#### Scenario: 成功拖拽到现有窗口
- **WHEN** 源标签和目标窗口在执行前仍然存在
- **THEN** 系统移动真实标签、刷新窗口卡片并显示撤销入口

#### Scenario: 拖拽前标签已关闭
- **WHEN** 执行重校验时目标 `tabId` 已不存在
- **THEN** 系统跳过移动并报告标签已失效，不宣称成功

#### Scenario: 撤销窗口移动
- **WHEN** 用户撤销最近一次成功的窗口移动且原窗口仍存在
- **THEN** 系统尽力恢复标签的原窗口、索引、可恢复的原生组以及原组标题、颜色和折叠状态

#### Scenario: 撤销目标部分失效
- **WHEN** 部分标签或原窗口在撤销前已消失
- **THEN** 系统恢复仍可恢复的项目并明确报告跳过数量

### Requirement: 可按工作组织最低成本重排窗口
系统 SHALL 为每个非空工作规划一个目标窗口，使保留在原窗口的可操作标签数全局最大；系统 SHALL 优先复用现有窗口且仅在现有窗口不足时创建新窗口。

#### Scenario: 多个工作争用同一窗口
- **WHEN** 局部贪心选择不能得到最低总移动数
- **THEN** 系统使用全局一一匹配选择总移动数更少的映射

#### Scenario: 工作数少于现有窗口数
- **WHEN** 非空工作数量不超过普通窗口数量
- **THEN** 系统不为这些工作创建新窗口

#### Scenario: 工作数多于现有窗口数
- **WHEN** 非空工作数量超过可复用普通窗口数量
- **THEN** 系统仅为无法匹配现有窗口的工作创建必要数量的新窗口

#### Scenario: 用户尚未确认批量重排
- **WHEN** 用户点击“按照现有组织重新分配窗口”
- **THEN** 系统先展示工作数、移动数、复用/新建窗口数、保护标签数和混合组数，确认前不移动标签

### Requirement: 单工作创建标签组同时聚合窗口
系统 SHALL 在用户对一个工作执行“创建标签组”时，先选择或创建该工作的目标窗口、移动全部可操作标签，再创建或安全复用 Chrome 原生标签组。

#### Scenario: 工作标签全部共享同一有效原生组
- **WHEN** 工作内所有可操作标签具有相同且有效的 `groupId`
- **THEN** 系统复用该原生组并更新其窗口位置和标题

#### Scenario: 工作标签没有共享同一有效原生组
- **WHEN** 标签处于多个组、未分组或只有部分标签在同一组
- **THEN** 系统在目标窗口中为该工作创建新的原生标签组

#### Scenario: 另一个原生组具有相同标题
- **WHEN** 存在标题与工作名称相同但成员不属于该工作的原生组
- **THEN** 系统不因标题相同而复用该组

#### Scenario: 执行前可复用组的成员已经变化
- **WHEN** 规划完成后原生组加入了不属于该工作的标签
- **THEN** 系统执行前重新查询完整成员，不整体移动或复用该组，并为仍有效的工作标签创建新组

### Requirement: 批量重排保护特殊标签并报告部分失败
系统 MUST 排除置顶标签、内部页面、隐身标签和非普通窗口标签，并 SHALL 在原生组混合多个工作或待整理页面时按标签拆分且在确认摘要中披露。

#### Scenario: 工作包含置顶标签
- **WHEN** 批量重排规划遇到置顶标签
- **THEN** 系统保持其窗口和 pinned 状态不变，并把它计入保护数量

#### Scenario: 原生组混合多个工作或待整理页面
- **WHEN** 一个 Chrome 原生组同时包含目标工作和其他工作标签或待整理页面
- **THEN** 系统不整体移动该组，而是按可操作标签移动并把该组计入混合组数量

#### Scenario: 批量执行中部分 Chrome API 调用失败
- **WHEN** 一个或多个移动或分组步骤失败
- **THEN** 系统记录已成功和失败项目、尽力补偿可恢复步骤，并显示真实结果而非统一成功提示

## Context

快捷库按关键词派生分组，颜色使用独立本地键保存。既有管理器已支持页面和别名 CRUD、颜色表单与备份；卡片色块目前只是 span，弹窗自身滚动。用户已授权连续完成、自审，不逐项等待确认。

## Goals / Non-Goals

目标：直接从卡片编辑该组、重命名保留颜色和子项、滚动时关闭按钮可见、中英文与窄屏可用。
非目标：重新设计卡片、增加新存储模型、批量编辑事务、改备份格式、网页防重或 Blue。

## Decisions

1. 复用现有管理器并增加可选分组上下文，优于新建独立编辑弹窗（重复 CRUD）。分组编辑展示组名、现有颜色表单、当前组的页面列表与新增/编辑表单；点击色块聚焦 HEX/RGB 输入。普通“管理”保持全量视图。
2. 卡片组名与色块保持原布局，色块外包原生 button，右上角页面数旁增加轻量“编辑”按钮；具备可读名称、焦点样式，不嵌套页面打开按钮。
3. `renameGroup(oldKeyword, newKeyword)` 复用现有 Web Lock 与串行队列，读取最新映射及颜色；空名、源组消失、目标组重名或数据损坏时不写入。改名一次 `storage.set` 同时更新两个键；保留 ID、URL、别名、顺序及当前颜色，不做隐式分组合并。
4. 页面和颜色各自使用既有保存按钮，失败保留草稿，不设置全组“保存所有”按钮；重命名成功后更新分组上下文。当前组的页面关键词字段隐藏并固定，编辑不会意外挪到别组。删除仍需二次确认；删空后允许在原组上下文继续新增。
5. 原生 dialog 固定外壳，标题和关闭按钮在独立顶栏，`.keyword-dialog-body` 单独滚动；保留 Esc、焦点恢复和隐私模式关闭机制。使用既有主题色、字体和尺寸，不换视觉风格。

## Risks / Trade-offs

- 重命名会影响组名搜索 → 提交后原子更新所有子项及颜色，已打开网页不受影响；失败保留输入，重名明确拒绝。
- 多仪表盘同时修改 → 使用现有同源 Web Lock，提交时读最新状态；外部删除源组时不创建空新组，不覆盖其他组。
- 窄屏与长名称 → 组名省略、按钮不挤出、弹窗正文滚动；用 390/768/1365 宽度及浅深主题验证。
- 颜色读取损坏 → 原映射可读，配色及改名停止写入并报错，避免静默丢配色。

## Migration Plan

不迁移数据和权限，不操作真实 Chrome 标签。开发在 `yzh/feat/shortcut-group-editor`，从含休眠修复与颜色的当前基线开发；验证后增量同步原扩展目录，保留私有配置、诊断文件和 Blue，再按既有授权提交推送同名分支，不合并 main。

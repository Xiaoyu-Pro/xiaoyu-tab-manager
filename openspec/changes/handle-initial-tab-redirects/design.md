## Context

真实记录中，新标签前台、普通窗口、有来源、未置顶或分组。初始加载地址 A 无匹配；711 毫秒后，在同一标签加载地址 B，此时已有两个符合条件的完整同址标签。代码在 A 已删除候选资格，因此不会评估 B。

隔离 Chrome 对照实测：网页脚本跳转、同一文档改址，以及主动触发第二次导航，都能发出同样的两次 `tabs.onUpdated` 地址变化。试验扩展使用导航权限后，脚本跳转有 `client_redirect`；同文档改址为 `onHistoryStateUpdated`，不带跳转标记。真实飞书记录尚未确认属于哪种。

## Goals / Non-Goals

- 覆盖此次“首个地址不匹配、加载期间出现精确匹配”的前台链接路径。
- 保留首个地址直接命中的既有自动行为；不改变 Blue、后台打开、旧页导航、手动刷新、会话恢复或匹配精度。

## Decisions

- 首次地址无合格目标时，只对已有明确来源的前台链接保留最多 2 秒的后续观察资格，从首地址开始计时，不因多跳续期，不越过加载完成。只看同一新标签的新已提交地址；不限制域名，不调整 URL，不扫描已有标签的导航。
- 后续尝试要求来源 ID 不变、源标签仍在前台且未被保护。命中后消耗资格，复用现有“先切换，复核成功后关闭新页并发一次通知”的流程。用户不需要点通知。
- 会话存储只保留现有标签/窗口 ID 及新增的来源标签 ID、首次加载时间，不保存网址或页面标题。不新增权限。

## Risks / Trade-offs

- 标签 API 不能严格区分这一短窗口内、仍保留同一来源的手动页面内跳转与自动变址。按用户确认的自动策略，二者若满足上述所有条件都可能复用；不会延伸到已完成的加载、来源变更或后台页。
- 不等待超过两秒或首个加载完成后的跳转。操作失败或复核失败时保留新页，不尝试其他跳转。
